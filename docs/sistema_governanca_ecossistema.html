Sistema de Governança do Ecossistema Cara Core

Este documento define o caracore-tools como núcleo operacional de governança para:

  • releases
  • roadmap
  • automação de delivery
  • sincronização matriz/lojas por aplicação

Objetivo

Reduzir estresse operacional com um fluxo único, rastreável e reproduzível.

Componentes

  1. Orquestração de delivery:
  • scripts/ecosystem_delivery.py
  • scripts/ecosystem-delivery-map.json
  1. Governança e gate:
  • scripts/ecosystem_governance.py
  • scripts/ecosystem-governance-catalog.json
  1. Governança de branches:
  • scripts/ecosystem_branch_governance.py
  • campos sourceBranchTarget e releaseBranchTarget no catálogo
  1. Wrappers por aplicação:
  • scripts/run_delivery_ete.py
  • scripts/run_delivery_circuito.py
  • scripts/run_delivery_hub.py
  • scripts/run_delivery_ink.py
  • scripts/run_delivery_ru.py
  • scripts/run_delivery_cso.py
  • suporte comum: scripts/sync_delivery_site_to_releases_docs.py

Fluxo recomendado por release

  1. Dashboard de governança:
 python scripts/ecosystem_governance.py dashboard
  1. Janela de calendário (próximos marcos):
 python scripts/ecosystem_governance.py roadmap --window-days 180

2.5. Alinhamento de branch por app (fonte e releases):

 python scripts/ecosystem_branch_governance.py status 
 python scripts/ecosystem_branch_governance.py align --dry-run
  1. Gate por aplicação (No-Go/Go):
 python scripts/ecosystem_governance.py gate --app pdv --strict
  1. Geração de evidência formal do gate:
 python scripts/ecosystem_governance.py report --app pdv
  1. Simulação de delivery:
 python scripts/ecosystem_delivery.py run --app pdv --dry-run
  1. Delivery efetivo:
 python scripts/ecosystem_delivery.py run --app pdv

Criticidade do gate

O gate avalia quatro eixos:

  • Segurança (tokens/credenciais de publicação)
  • Consistência Delivery-Matriz-Loja
  • Automação (comando de release existente)
  • Integridade Git (repos limpos)

Regra:

  • Falha crítica => BLOQUEADO
  • Sem falha crítica e com ressalvas => APROVADO COM RESSALVAS
  • Sem ressalvas => APROVADO

Evidências

Relatórios Markdown do gate são gerados localmente em (não publicados no site):

  • reports/governance/

Padrão de arquivo:

  • GATE_<app>_<timestamp>.md

Política operacional

  • Sempre executar dashboard e gate antes de publicar.
  • Sempre executar -DryRun antes de delivery efetivo.
  • Usar commits atômicos por app e por repositório.
  • Publicar somente com trilha de evidência do gate.

Regra de artefatos binários por canal

Diretriz obrigatória para o PDV:

  • O executável e checksums do PDV não devem ser publicados pela matriz (caracore-site).
  • O delivery de binários do PDV deve ocorrer somente na loja oficial de releases:

https://github.com/chmulato/caracore-pdv-releases.

  • A matriz deve publicar apenas conteúdo institucional, documentação e links para a loja.

O gate de governança bloqueia publicação quando detectar alteração em artefatos proibidos na matriz do PDV.

Regra geral do ecossistema:

  • Cada aplicação com entrega de artefato deve publicar no seu repositório dedicado com sufixo -releases.
  • O repositório de matriz (caracore-site) permanece como canal institucional de apresentação, documentação e direcionamento.
  • O gate valida conformidade do canal oficial por app (checagem de padrão *-releases).

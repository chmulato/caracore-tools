Sistema de Governanca do Ecossistema Cara Core

Este documento define o caracore-tools como nucleo operacional de governanca para:

  • releases
  • roadmap
  • automacao de delivery
  • sincronizacao matriz/lojas por aplicacao

Objetivo

Reduzir estresse operacional com um fluxo unico, rastreavel e reproduzivel.

Componentes

  1. Orquestracao de delivery:
  • scripts/ecosystem_delivery.py
  • scripts/ecosystem-delivery-map.json
  1. Governanca e gate:
  • scripts/ecosystem_governance.py
  • scripts/ecosystem-governance-catalog.json
  1. Governanca de branches:
  • scripts/ecosystem_branch_governance.py
  • campos sourceBranchTarget e releaseBranchTarget no catalogo
  1. Wrappers por aplicacao:
  • scripts/run_delivery_ete.py
  • scripts/run_delivery_circuito.py
  • scripts/run_delivery_hub.py
  • scripts/run_delivery_ink.py
  • scripts/run_delivery_ru.py
  • scripts/run_delivery_cso.py
  • suporte comum: scripts/sync_delivery_site_to_releases_docs.py

Fluxo recomendado por release

  1. Dashboard de governanca:
 python scripts/ecosystem_governance.py dashboard
  1. Janela de calendario (proximos marcos):
 python scripts/ecosystem_governance.py roadmap --window-days 180

2.5. Alinhamento de branch por app (fonte e releases):

 python scripts/ecosystem_branch_governance.py status 
 python scripts/ecosystem_branch_governance.py align --dry-run
  1. Gate por aplicacao (No-Go/Go):
 python scripts/ecosystem_governance.py gate --app pdv --strict
  1. Geracao de evidencia formal do gate:
 python scripts/ecosystem_governance.py report --app pdv
  1. Simulacao de delivery:
 python scripts/ecosystem_delivery.py run --app pdv --dry-run
  1. Delivery efetivo:
 python scripts/ecosystem_delivery.py run --app pdv

Criticidade do gate

O gate avalia quatro eixos:

  • Seguranca (tokens/credenciais de publicacao)
  • Consistencia Delivery-Matriz-Loja
  • Automacao (comando de release existente)
  • Integridade Git (repos limpos)

Regra:

  • Falha critica => BLOQUEADO
  • Sem falha critica e com ressalvas => APROVADO COM RESSALVAS
  • Sem ressalvas => APROVADO

Evidencias

Relatorios Markdown do gate sao gerados localmente em (nao publicados no site):

  • reports/governance/

Padrao de arquivo:

  • GATE_<app>_<timestamp>.md

Politica operacional

  • Sempre executar dashboard e gate antes de publicar.
  • Sempre executar -DryRun antes de delivery efetivo.
  • Usar commits atomicos por app e por repositorio.
  • Publicar somente com trilha de evidencia do gate.

Regra de artefatos binarios por canal

Diretriz obrigatoria para o PDV:

  • O executavel e checksums do PDV nao devem ser publicados pela matriz (caracore-site).
  • O delivery de binarios do PDV deve ocorrer somente na loja oficial de releases:

https://github.com/chmulato/caracore-pdv-releases.

  • A matriz deve publicar apenas conteudo institucional, documentacao e links para a loja.

O gate de governanca bloqueia publicacao quando detectar alteracao em artefatos proibidos na matriz do PDV.

Regra geral do ecossistema:

  • Cada aplicacao com entrega de artefato deve publicar no seu repositorio dedicado com sufixo -releases.
  • O repositorio de matriz (caracore-site) permanece como canal institucional de apresentacao, documentacao e direcionamento.
  • O gate valida conformidade do canal oficial por app (checagem de padrao *-releases).

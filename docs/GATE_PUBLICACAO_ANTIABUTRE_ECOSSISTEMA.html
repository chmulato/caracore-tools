Gate de Publicação Antiabutre - Ecossistema Cara Core

Data base: 2026-03-15

Escopo: todos os repositórios de produto, releases e site institucional

Objetivo: impedir exposição, captura oportunista e incoerência comercial antes de qualquer publicação

1. Regra de Ouro

Nenhuma publicação segue para ambiente público sem aprovação completa deste gate.

Aprovação mínima:

  • Segurança: APROVADO
  • Propriedade e licença: APROVADO
  • Consistência comercial e cronograma: APROVADO
  • Evidência de integridade: APROVADO

Se qualquer item crítico falhar, status final = BLOQUEADO.

2. Checklist Obrigatório (Go/No-Go)

A. Segurança e Exposição

  • [ ] Zero segredo em repositórios públicos (.env real, senha, token, chave privada)
  • [ ] Zero artefato sensível em lojas/releases (logs internos, dumps, backups)
  • [ ] Dependências e CVEs com status aceitável para release
  • [ ] Regras de protecao de credenciais validadas no build/revisão

Evidências esperadas:

  • Relatório de segurança atualizado
  • Busca por padrões sensiveis sem achados críticos

B. Propriedade Intelectual e Licença

  • [ ] Licença coerente com política do produto (proprietario, free, premium)
  • [ ] Copyright e aviso de uso corretos
  • [ ] Nenhuma contradicao entre README, loja e documento legal

Evidências esperadas:

  • Revisão de README e LICENSE
  • Verificacao cruzada com páginas de release

C. Consistência Comercial e Cronograma

  • [ ] Data oficial de publicação alinhada em todos os documentos oficiais
  • [ ] Nome do produto, versão e proposta comercial consistentes
  • [ ] Sem mensagem ambigua sobre status (beta, produção, roadmap)

Evidências esperadas:

  • Lista de arquivos oficiais revisados
  • Dif consolidado de alterações de cronograma/comercial

D. Saude Técnica

  • [ ] Build principal sem erro bloqueante
  • [ ] Suite de testes em nivel aceitável para release
  • [ ] Sem regressão funcional crítica conhecida

Evidências esperadas:

  • Log de build/test
  • Sumario de riscos técnicos

E. Integridade e Rastreabilidade

  • [ ] Commit único de release com mensagem clara
  • [ ] Tag de checkpoint de segurança criada e publicada
  • [ ] Manifesto/hash dos arquivos críticos anexado
  • [ ] Registro de aprovação final (quem aprovou, quando, escopo)

Evidências esperadas:

  • Commit SHA
  • Tag de segurança
  • SHA256 dos arquivos oficiais

3. Matriz de Severidade (Decisão)

Critica:

  • Segredo exposto
  • Inconsistência de licença/propriedade
  • Divergencia de data oficial em material de publicação
  • Falha de build/test que compromete release

Alta:

  • Risco de interpretacao comercial incorreta
  • Evidência de integridade incompleta

Media:

  • Warnings não bloqueantes com plano de correcao

Baixa:

  • Ajustes editoriais sem impacto legal/comercial/técnico

Regra de decisão:

  • Qualquer Critica = BLOQUEADO
  • Mais de 2 Altas = BLOQUEADO
  • Somente Medias/Baixas = APROVADO COM RESSALVAS

5. Cadência Recomendada Ate 08/11/2028

  • Gate completo em toda release pública
  • Revisão mensal de risco do ecossistema
  • Auditoria trimestral de lojas e licenças
  • Simulação de incidente semestral (segredo vazado, conflito de data, erro de release)

6. Comando de Execução Operacional (Resumo)

  1. Rodar checklist A-E.
  2. Coletar evidências mínimas.
  3. Classificar severidade.
  4. Decidir Go/No-Go.
  5. Registrar ata.
  6. Publicar somente com tag de segurança.
